
### 현재 흐름

BreachSourceComponent를 가진 액터는 BeginPlay BreachOption에 따라서 CutMesh를 미리 캐시한다.
BreachableMeshComponent에 Hit하거나 Trace했을때 Breach를 시작한다.
Hit -> BreachableMeshComponent의 OnHit에서 
ReceiveComponentDamage Trace면 Trace한 함수에서 ApplyPointDamage하면
BreachableMeshComponent가 해당 데미지를 받아서 BreachableMesh까지 전달해준다
(첫 충돌은 UBreachableMeshComponent::ReceiveComponentDamage)
(두번째 충돌은 UBreachableDynamicMeshComponent::ReceiveComponentDamage)

이제 Breach가 시작된다.
Hit정보의 SourceActor에 BreachSourceComponent가 있는지 확인하고 BreachSourceComponent의 CutMesh를 가져온다.
초기 Hit이면 DynamicMeshProxy를 추가하고, 현재 메시 렌더링/충돌은 꺼준다.

BreachableMesh 월드상의 Bound를 가져와서, CutMesh의 Hit지점 기준부터 CutMesh를 얼마나 길게 변형해야할지 정한다.
이때 HitImpact로부터  각 AABB의 꼭짓점으로 향하는 벡터를 구하고, HitDirection과 내적한다.
이 값으로 AABB가 Direction으로의 깊이를 구하고, 2차원 평면의 CutterMesh를 깊이만큼 늘릴수있는 Transform을 반환한다.

해당 Transform으로 Boolean Difference연산 수행한다.

결과 메시를 Proxy에 세팅한다.


#### 흐름 소유는 우선 그대로 가져간다.
서버 : 충돌, 파괴상태 갱신 (추후 변경 생각중)
클라 : 파괴상태 복제

### 현재 흐름에서의 클라-서버 처리

1. 서버에서 충돌/피격이 일어나서 메시 절단 발생
	1. a. 클라이언트에서도 똑같은 위치에 똑같게 절단이 발생해야 한다.
2. 어떤 메시인지 알 수 있게 충돌한 Component ID를 전달
3. 충돌위치, 서버가 절단에 실제 사용한 Direction, BreachSourceOption, 절단순서를 클라에게 전달한다
4. 절단 순서를 맞추기 위해 앞 번호가 들어올때까지 대기하고, 이후 자기 차례가되면  절단을 발생시킨다.
