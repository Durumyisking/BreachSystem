# R6 표면 파괴: 직접 만들 기능과 엔진 코드 안내

2026-10-12 수정. 사용자가 직접 코드를 작성하기 위한 작업 목록이다. 기존 기능 호환·보존·이전은 개발 요구가 아니다. 아래 클래스·함수 이름은 직접 만들 대상으로 제안한 이름이며, **엔진 API**라고 표시한 것만 Unreal에 실제 존재한다. 코드 구현·빌드·게임 실행은 수행하지 않았다.

## 개발 방식과 범위

벽을 만들고 → 클릭한 곳을 자르고 → 실제 구멍과 충돌을 만들고 → 재료별 파괴·덩어리 탈락·장식·멀티플레이를 붙인다. 각 기능이 눈에 보이거나 로그로 확인될 때 다음 기능으로 간다. 기존 GC 실험의 호환 계층, 에셋 이전, GameFeature 전환, 다른 프로젝트 이식은 이번 개발 과제로 넣지 않는다.

자료: `C:\Users\csh\Documents\카카오톡 받은 파일\surface-destruction-guide\explanation.html`, `README.txt`, `lab.js`. [GDC 2016 원문](https://media.gdcvault.com/gdc2016/Presentations/LHeureux_Julien_Art_Of_Destruction.pdf)의 34–49쪽을 참고한다. 2D 표면을 절단하고 3D로 돌출하는 구조를 사용하되, 엔진의 제약 Delaunay와 아래 누적 피해 규칙은 자체 구현 선택이다.

첫 테스트 벽은 **로컬 XY 평면, 두께 Z, 폭 400cm·높이 300cm·두께 10cm**로 직접 생성한다. Actor를 회전해 벽처럼 세운다. 초기 Scale은 1로 두고 크기는 Width/Height/Thickness로 바꾼다. 임의 StaticMesh에서 평면을 자동 추출하는 기능은 만들지 않는다. 수치는 작은 예제를 재현하기 위한 값이다.

## 처음 만들 파일과 데이터

처음에는 아래 네 묶음이면 된다. 나중 기능 때문에 처음부터 모든 파일을 만들지 않는다.

- `Public/BreachableSurfaceComponent.h`, `Private/BreachableSurfaceComponent.cpp`: `UDynamicMeshComponent`를 상속하는 벽 컴포넌트. 초기화, 피격, 메시 적용, 충돌 갱신을 담당한다.
- `Public/BreachSurfaceTypes.h`: 벽 크기, 현재 영역, 절단 입력의 일반 C++ 구조체. Blueprint에 편집할 항목만 USTRUCT/UPROPERTY로 노출한다.
- `Private/BreachSurfaceGeometry.h/.cpp`: 커터 생성, 차집합, 삼각분할, 메시 생성 함수. World나 Actor를 요구하지 않게 한다.
- 테스트 Actor 또는 Blueprint: 위 컴포넌트 한 개를 배치하고 Reset/고정 위치 절단/클릭 절단을 호출한다. 처음에는 총기와 연결할 필요가 없다.

처음 저장할 값은 Width, Height, Thickness와 `TArray<UE::Geometry::FGeneralPolygon2d> RemainingRegions`다. 한 FGeneralPolygon2d는 외곽선 하나와 여러 hole을 가진다. 배열은 벽이 여러 영역으로 분리되는 경우를 담는다. 원래 사각형과 현재 남은 영역을 구분한다.

실험용 절단 입력은 SurfacePoint, Radius, Seed로 시작한다. 사격 연결 때 WorldHit, ShotDirection, AttackType, Damage를 추가한다. 누적 피해·네트워크 데이터는 해당 기능에 도달했을 때 추가한다.

빌드 모듈은 Core/CoreUObject/Engine 외에 GeometryCore, GeometryFramework, GeometryAlgorithms를 사용한다. 공개 헤더에 노출한 엔진 타입의 모듈은 Public 의존성, .cpp 안에서만 쓰는 GeometryAlgorithms는 Private 의존성으로 둔다. GeometryProcessing 플러그인 의존성도 필요하다. 현재 BreachSystem.uplugin에는 이미 선언되어 있다.

## 01. 폭·높이를 입력하면 사각형 벽을 표시하기

**직접 만들 함수**

- `InitializeSurface(Width, Height, Thickness)`: 네 모서리로 초기 영역 한 개를 만들고 RemainingRegions에 저장한다.
- `BuildFlatPreview(Region)`: 첫 실험에서는 네 정점과 삼각형 두 개로 앞면만 만든다.
- `ResetSurface()`: 변경된 영역을 버리고 초기 사각형을 다시 표시한다.

**입출력**: 400×300 입력 → (-200,-150), (200,-150), (200,150), (-200,150)의 사각형. FPolygon2d의 정점 배열에는 첫 정점을 맨 끝에 중복 추가하지 않는다.

**엔진 API**: `FPolygon2d::AppendVertex`, `FGeneralPolygon2d(Outer)`, `FDynamicMesh3::AppendVertex`, `AppendTriangle`, `UDynamicMeshComponent::SetMesh(MoveTemp(Mesh))`.

**확인**: 초기 2D 면적은 120,000cm², 앞면 삼각형은 2개. 크기를 바꾸고 Reset했을 때 입력 크기로 다시 나온다. 첫 앞면만 있는 상태에서는 뒤에서 보이지 않는 것이 두께 구현 실패를 뜻하지 않는다.

## 02. 클릭한 위치를 벽의 2D 좌표로 바꾸기

**직접 만들 함수**

- `WorldToSurface(WorldPoint) -> FVector2d`: 컴포넌트 역변환을 적용하고 Local.X/Y를 반환한다.
- `SurfaceToWorld(Point2D, Depth) -> FVector`: (X,Y,Depth)를 월드로 변환한다.
- `DebugDrawSurface()`: 외곽선과 hole의 연속 정점, 마지막→첫 정점을 DrawDebugLine으로 잇는다.

**엔진 API**: `FTransform::InverseTransformPosition`, `TransformPosition`, `DrawDebugLine`, `DrawDebugPoint`, `DrawDebugString`.

**확인**: 중앙 클릭은 (0,0), 오른쪽 가장자리는 x=200 근처다. 벽을 이동·90도 회전해도 같은 벽 위치는 같은 2D 값이다. 앞뒤 면의 Z는 평면 투영에서 버리고 두께 생성에 따로 쓴다. 첫 단계는 Scale 1을 전제로 한다.

## 03. 맞은 곳 주변에 절단용 다각형 만들기

**직접 만들 함수**

- `MakeCircleCutter(Center, Radius, Segments) -> FGeneralPolygon2d`.
- `MakeBoxCutter(Center, Size, Angle) -> FGeneralPolygon2d`.
- `MakeRoughCutter(Center, Radius, Segments, Seed, Roughness) -> FGeneralPolygon2d`.

**처리**: 원의 i번째 점은 Center + Radius×(cos(2πi/N), sin(2πi/N)). 불규칙형은 각도를 순서대로 유지하고 반경을 seed 기반으로 변화시킨다. 음수 반경·3개 미만 정점·자기 교차는 거부한다.

**엔진 API**: FPolygon2d, FMath의 삼각함수, `FRandomStream`. 난수 생성 순서도 고정한다.

**확인**: Radius=20cm, Segments=16인 커터를 벽 중앙에 주황색 선으로 표시한다. 동일 seed는 동일 정점, 다른 seed는 다른 거친 경계다. 아직 벽은 제거하지 않는다.

## 04. 절단할 때마다 남은 벽의 윤곽 갱신하기

**직접 만들 함수**: `CutSurface(CurrentRegions, Cutters, OutRegions) -> 연산 성공 여부`.

**엔진 API**: `UE::Geometry::PolygonsDifference(CurrentRegions, Cutters, OutRegions)`.

**처리**: 임시 OutRegions에 연산한다. 성공하면 그 결과를 표시한다. false는 연산 실패이고, 성공하면서 배열이 빈 경우는 벽 전체 제거다. 원래 사각형 대신 현재 RemainingRegions를 다음 절단의 입력으로 사용한다.

**확인할 고정 입력**

- 중앙의 작은 커터: 영역 1개, hole 1개.
- 오른쪽 테두리를 넘는 커터: 닫힌 hole 대신 외곽에 홈.
- 겹치는 두 커터: 합쳐진 구멍, 첫 구멍이 다시 채워지지 않음.
- 높이 300cm를 완전히 넘는 중앙 세로 띠: 좌우 영역 2개.
- 벽보다 큰 커터: 성공 + 영역 0개.
- 같은 커터 재적용: 기하 변화 없음.

**디버그**: 영역마다 색을 다르게 하고 외곽·hole 수와 면적을 표시한다. 여기까지는 2D 선만으로 개발해도 된다.

## 05. 구멍을 덮지 않는 앞면·뒷면 만들기

**직접 만들 함수**: `TriangulateRegion(Region, OutVertices, OutTriangles) -> bool`.

**엔진 API**: `FConstrainedDelaunay2d`, `Add(Region)`, `Triangulate()`, 출력 `Vertices`와 `Triangles`.

**처리**: 영역마다 삼각분할 객체를 새로 만든다. 일반 다각형을 Add하면 외곽과 hole이 구분되어 들어간다. 출력 winding을 지정한다. 출력 정점과 인덱스를 함께 사용한다. z=+Thickness/2에 앞면을 만들고 z=-Thickness/2에는 반대 winding으로 뒷면을 만든다.

**확인**: hole을 가로질러 덮는 삼각형이 없어야 한다. 앞면 삼각형 면적 합을 남은 2D 영역 면적과 비교한다. 실패 반환을 무시하고 일부 삼각형만 적용하지 않는다. Unreal에서 실제 앞뒤 표시 방향도 확인한다.

## 06. 구멍 안쪽과 벽 외곽에 두께 만들기

**직접 만들 함수**

- `AppendBoundarySides(Boundary, Thickness, IsHole, Mesh)`.
- `BuildSurfaceMesh(Regions, Thickness, OutMesh)`는 05의 앞뒤 면과 이 옆면을 합친다.

**처리**: 경계의 A→B마다 앞A·앞B·뒤A·뒤B를 삼각형 두 개로 연결한다. 외곽과 hole의 방향에 맞춰 바깥쪽을 향하게 만든다. 정점 번호는 AppendVertex의 반환값으로 대응시킨다.

**엔진 API**: `FDynamicMesh3::AppendVertex`, `AppendTriangle`. AppendTriangle의 실패 반환도 검사한다.

**확인**: 옆에서 보면 10cm 두께, 구멍을 들여다보면 절단면이 보인다. 외곽 옆면과 hole 옆면이 모두 있어야 한다. 첫 버전은 bowtie 같은 비정상 접합 후보를 거부하고 이전 결과를 유지한다.

## 07. 겉면·절단면 재질과 UV 붙이기

**직접 만들 함수**

- `AssignSurfaceAttributes(Mesh, OriginalWidth, OriginalHeight)`.
- `AssignBoundaryAttributes(Boundary, Thickness, Mesh)`.

**처리**: 앞뒤 면은 초기 평면 좌표로 UV를 계산한다. 예: u=(x+Width/2)/Width, v=(y+Height/2)/Height. 새 Bounds로 매번 정규화하지 않는다. 측면은 경계 누적 길이/텍스처 반복 길이와 두께 좌표로 UV를 만든다.

**엔진 API**: `FDynamicMesh3::EnableAttributes`, `Attributes()->PrimaryUV()`, `PrimaryNormals()`, `EnableMaterialID()`, `GetMaterialID()->SetValue`. Overlay에는 `AppendElement`, `SetTriangle`을 사용한다. Overlay element ID와 메시 vertex ID는 별개다.

**확인**: 표면과 속 재질이 다르게 나오고, 반복 절단해도 겉면 그림이 움직이지 않는다. 앞면과 측면의 법선 element를 분리해 단면이 둥글게 보간되지 않게 한다. 뒤쪽 UV의 거울 여부는 재료 규칙으로 명시한다.

## 08. 보이는 구멍을 총알·캐릭터가 통과하게 만들기

**직접 만들 함수**: `ApplySurfaceResult(Regions, Mesh)`.

**처리**: 후보 형상을 확인한 뒤 컴포넌트 메시를 교체하고 충돌을 갱신한다. 초기에는 움직이지 않는 벽과 동기 cooking으로 순서를 단순하게 확인한다. 벽 전체가 제거되면 이전 메시와 충돌을 모두 비운다.

**엔진 API**: `SetMesh`, `SetComplexAsSimpleCollisionEnabled`, `SetDeferredCollisionUpdatesEnabled`, `UpdateCollision`. 지연 갱신으로 여러 메시 변경을 묶은 뒤 충돌을 한 번 갱신할 수 있다. `UpdateCollision(true)`의 true는 'pending일 때만'이라는 뜻이며 강제 갱신 스위치가 아니다.

**확인**: 작은 구멍을 통과하는 Trace는 벽에 맞지 않고, 남은 부분의 Trace는 맞는다. 캐릭터 capsule보다 충분히 큰 구멍은 통과한다. 화면만 뚫렸는데 충돌이 남거나 그 반대인 경우를 따로 기록한다. Complex-as-Simple 벽 자체를 동적 물리 파편으로 사용하지 않는다.

## 09. 총알·근접공격·폭발의 입력 연결하기

**직접 만들 함수**: `ApplySurfaceHit(WorldHit, ShotDirection, AttackProfile)`.

**처리**: AttackProfile에서 커터 종류·크기·피해·영향 반경을 읽고 02→03→04→05/06/07→08을 호출한다. 초기에는 버튼으로 같은 함수를 호출해 검증하고, 그 뒤 실제 무기 입력을 연결한다. 다수 pellet은 순서대로 적용한 결과와 한 번의 합집합 결과의 차이를 정책에 맞게 검증한다.

**확인**: 총알은 작은 구멍, 근접은 큰 범위, 폭발은 주변 벽 중 실제 영향을 받는 면을 제거한다. 이 단계에서 공격 프로필 수치는 자체 테스트값이다. 표면 법선 ImpactNormal과 총알 진행 방향 ShotDirection을 섞지 않는다. 첫 절단 규칙은 벽 법선 방향 관통이며 비스듬한 입구·출구 형상은 표현하지 않는다.

## 10. 재료마다 다르게 깨지는 모양 만들기

**직접 만들 함수**

- `GenerateMaterialCutter(Hit, MaterialRule, Seed)`.
- `SelectPatternCells(ImpactArea, PatternCells)`.
- `MapPatternUVToSurface(UVPoint, Mapping)`.

**처리**: 석고는 거친 윤곽, 목재는 결 방향으로 긴 윤곽, 벽돌은 미리 만든 벡터 셀 선택, 유리는 방사형·동심형 선으로 구성한 셀 패턴을 만든다. 한 재료씩 붙인다. 패턴이 원 내부 조각을 출력할 때는 셀과 현재 벽의 교집합을 구한다.

**엔진 API**: `PolygonsIntersection`, `PolygonsUnion`, 이후 동일한 Difference 경로. 초기 벡터 패턴은 Data Asset에 직접 입력해도 된다. Texture Cutter를 위해 매번 이미지 픽셀을 분석할 필요는 없다.

**확인**: 벽돌 줄눈에 맞춰 경계가 생기고, UV 반복·오프셋을 바꾸면 표시 무늬와 CPU 패턴이 함께 움직인다. 유리 셀 경계와 실제로 제거할 셀 선택은 구분한다. 원문은 커터 종류를 설명하며 여기의 선택 규칙을 그대로 지정하지 않는다.

## 11. 여러 발을 맞으면 주변 덩어리가 떨어지게 만들기

**직접 만들 함수**

- `BuildDamageCells(MaterialPattern)`: 안정적인 셀 ID와 경계를 만든다.
- `AccumulateDamage(Hit, Damage, InfluenceArea)`: 벽별 누적값을 갱신한다.
- `CollectFailedCells() -> 제거할 셀 경계`.

**처리**: 기하 삼각형과 피해 셀을 별도로 저장한다. 영향 범위·현재 재료·셀의 교집합 면적으로 한 발의 피해를 가중 분배한다. 가중치 합을 정규화하고 임계값을 넘은 셀의 남은 면을 Difference로 제거한다. 피해 계산은 직접 구멍을 빼기 전의 실제 피격 재료를 기준으로 한다.

**확인**: 1개 셀에 피해 10, 임계값 30인 시험은 1·2회 유지, 3회 제거다. 이 값은 검증용이며 R6 수치가 아니다. 나뉜 셀마다 피해를 누적하므로 같은 발수라도 분산 사격 결과가 다르다. 구멍을 그대로 통과한 탄은 해당 벽의 피격으로 추가 집계하지 않는다.

**주의**: 누적 피해는 R6 공개 표면 기하 설명만으로 확정할 수 없는 자체 게임 규칙이다. 같은 커터 반복에서 형상이 바뀌지 않아도 실제 재료에 가해진 충격의 누적값은 바뀔 수 있다.

## 12. 주변이 끊긴 가운데 조각 제거하기

**직접 만들 함수**: `RemoveUnsupportedRegions(Regions, SupportAreas) -> 남길 영역과 제거 영역`.

**처리**: 최초 벽 가장자리에서 고정될 부분을 얇은 2D 지지 영역으로 지정한다. 절단 후 각 연결 영역과 지지 영역의 교집합 면적을 계산한다. 유효한 지지 영역과 면적을 가진 접촉이 없는 연결 영역을 제거한다. 이는 첫 지지 판정 모델이며 실제 응력 계산이 아니다.

**엔진 API**: `PolygonsIntersection`, FGeneralPolygon2d의 `SignedArea`. 면적 비교에는 정밀도에 맞는 허용 오차를 사용한다.

**확인**: 가운데를 둘러싼 절단을 완전히 닫으면 중앙 조각이 제거된다. 연결 다리가 남아 있으면 유지된다. 벽이 좌우로 분리돼도 양쪽이 각각 프레임에 닿아 있으면 둘 다 유지한다. 별도 하중 전달이 필요해질 때만 셀 인접 그래프·anchor에서의 BFS를 추가한다.

## 13. 벽에 붙은 그림·구멍 가장자리 장식 처리하기

**직접 만들 함수**

- `ClipSurfaceDecoration(DecorationRegion, RemainingRegions)`.
- `RemoveInvalidBoundaryDecorations(OldFeatures, NewBoundaries)`.
- `SpawnBoundaryDecorations(NewBoundaries, Seed)`.

**처리**: 포스터 같은 면 장식은 남은 벽과 교집합 후 다시 삼각분할한다. 새 정점의 UV는 원래 장식 매핑으로 얻는다. 석고 조각·나무 섬유는 부착한 논리적 경계 구간이 사라지면 제거한다. 초기에는 구간 일부가 잘려도 해당 장식을 제거하고 새 경계에 다시 배치한다.

**엔진 API**: `PolygonsIntersection`과 기존 메시 생성 함수, `UInstancedStaticMeshComponent`를 이용한 작은 장식 배치. 배열 index나 재삼각분할 Edge ID를 영구 식별자로 저장하지 않는다.

**확인**: 두 번째 구멍을 뚫으면 포스터도 잘리고, 사라진 구멍 가장자리의 장식이 공중에 남지 않는다. 표면 장식은 작은 오프셋 등으로 z-fighting을 피한다.

## 14. 날아가는 잔해·먼지·소리 붙이기

**직접 만들 함수**: `SpawnBreakEffects(RemovedArea, Hit, MaterialRule)`와 `RecycleDebris()`.

**처리**: 재료별 사전 제작 잔해 메시를 꺼내 배치·속도·수명을 준다. 작은 잔해는 단순 충돌을 사용하고 개수 한도를 둔다. 실제 잘린 모든 다각형을 물리 Actor로 만들지 않아도 된다. 장식용 잔해는 클라이언트에서만 만들어도 벽의 권위 상태는 같아야 한다.

**확인**: 파괴 시 잔해·먼지·소리가 나오고 시간이 지나면 회수된다. 효과를 꺼도 구멍과 플레이 충돌은 동일하다. 잔해를 플레이 장애물로 쓰려면 별도의 서버 판정 대상으로 승격해야 한다.

## 15. 다른 플레이어와 늦게 들어온 플레이어에게 같은 벽 보여주기

**직접 만들 기능/함수**

- 소유 Pawn/무기의 Server RPC에서 공격 입력을 받고 서버가 발사 조건과 Trace를 확인한다. 클라이언트가 소유하지 않은 벽에 Server RPC를 직접 호출하는 경로로 만들지 않는다.
- `MakeSurfaceSnapshot()` / `ApplySurfaceSnapshot()`: 남은 영역, 셀 피해, Surface ID, Generation, Revision을 직렬화하고 메시를 재생성한다. 처음은 이 스냅샷 방식으로 동작을 확인한다.
- `ApplyOrderedDestructionEvent(Event)`: 이후 평상시에는 순번·양자화된 입력·프로필 버전·seed로 재생한다. 서버도 같은 양자화 입력으로 계산한다.
- `RecoverSurfaceState()`: 누락·불일치·관련성 재진입에서 권위 스냅샷을 다시 적용한다. 중도 접속자는 스냅샷 기준 순번 이후 이벤트만 이어서 적용한다.

**데이터**: FGeneralPolygon2d를 그대로 자동 복제한다고 가정하지 않는다. 외곽/구멍별 점 배열을 표현하는 직렬화용 USTRUCT 등을 따로 만들고, 큰 스냅샷은 크기를 제한한 청크로 완전히 조립한 후 적용한다. seed가 같아도 연산 결과가 언제나 같다는 보장은 없다.

**확인**: 서버 1+클라이언트 2에서 같은 구멍과 충돌. 20번 파괴 후 새 클라이언트 접속 시 동일 복원. 임계값 직전 누적 피해도 복원되어 다음 한 발의 결과가 같아야 한다. 중복·누락·리셋 전 세대 이벤트를 검사한다.

## 16. 연속 파괴 비용 줄이고 실행 파일에서 확인하기

**직접 만들 기능**: `ReplayHitList`, 단계별 시간 측정, 상태 리셋, 연산 작업 큐와 오래된 결과 폐기.

**처리**: 1/10/50/100회 피격을 고정 입력으로 재생한다. 차집합·삼각분할·메시 적용·충돌·장식·네트워크를 각각 측정하고 가장 느린 부분부터 개선한다. 비동기화할 때 순수 기하 사본만 작업 스레드에서 처리하고 컴포넌트 적용은 게임 스레드에서 한다. Base Revision이 달라진 결과를 그대로 적용하지 않는다.

**확인**: 구멍이 누적돼도 실패 입력을 저장·재현할 수 있고 메모리/작업이 무한히 쌓이지 않는다. 맵 종료·벽 삭제 후 콜백이 남지 않는다. 실제 Server/Client 패키지에서 같은 기능이 실행된다. 렌더와 충돌 갱신 시점이 어긋나지 않는지도 확인한다.
